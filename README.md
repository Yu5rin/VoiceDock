# VoiceDock

**Web Speech API** を用いた音声入力ツールです。タスクトレイに常駐し、ホットキーひとつで
**任意の Windows アプリのテキスト入力欄**に日本語音声を直接入力できます。

チャット・メール等の短文入力を主用途とします。認識はブラウザ（Microsoft Edge / Google Chrome）の Web Speech API が行い、
本体は認識結果を受け取ってフォーカス中のアプリへキー入力として流し込みます。

> **プライバシーに関する注意**: 既定では Web Speech API が音声をクラウド（ブラウザの音声認識サービス）に
> 送信して認識します。機密性の高い内容の取り扱いにはご注意ください。
> なお、認識したテキストをログファイルに残すかは設定で選べます（**既定では保存しません**）。
> 新しめの Edge / Chrome では、設定の「可能なら端末内で認識する」を有効にすると、音声を
> クラウドに送らず端末内だけで認識できます（非対応環境では自動でクラウド認識に戻ります）。

## しくみ（アーキテクチャ）

Web Speech API はブラウザ内でのみ動作し、単体では他アプリへ入力できません。VoiceDock は次のブリッジ構成で
「ブラウザで認識 → 任意の Windows アプリへ入力」を実現します。

1. 本体が **ローカルサーバー（127.0.0.1）** を起動し、認識用ページを配信
2. **ブラウザ**（既定ブラウザに応じて Chrome / Edge）をアプリモードで画面外に常駐起動し、そのページを読み込む
3. ページが Web Speech API（`webkitSpeechRecognition`、日本語・連続認識）で認識し、確定テキストと音量を **WebSocket** で本体へ送信
4. 本体が辞書置換のうえ **SendInput** でフォーカス中のアプリに逐次入力（喋って区切るたびに入る“速記”的な動作）

## 主な機能

- **ホットキーでトグル録音**: 1 回押すと認識開始、もう一度で停止（初期値: `Ctrl+Space`、設定で変更可・衝突チェック付き）。トレイメニューからも開始/停止可能
- **全アプリへ直接キー入力**: 認識結果をフォーカス中の入力欄へ SendInput で流し込み。直接入力を受け付けないアプリ向けに**クリップボード貼り付け方式**も選択可（元のクリップボード内容は自動復元）
- **逐次入力（速記感）**: 確定したフレーズが出るたびに入力されます
- **認識中テキストのライブ表示**: 話している内容がオーバーレイにリアルタイム表示されます
- **音声コマンド（既定 ON）**: その語だけを発話すると対応する文字・操作を入力（文中では誤爆しません）
    - 操作: 「改行」「スペース」「タブ」（改行は Shift+Enter / Enter / Alt+Enter を設定で選択可）
    - 句読点: 「まる」→ 。 /「てん」→ 、 /「びっくり」→ ！ /「はてな」→ ？
    - 記号: 「アットマーク」→ @ /「コロン」「スラッシュ」「ハイフン」「アンダーバー」「ドット」「かっこ」「矢印」など
- **直前の入力を取り消す（既定 ON）**: 「とりけし」と発話、ホットキー（既定 `Ctrl+Shift+Space`）、またはトレイメニューから、直前に入力した分だけ削除
- **定型文（既定 ON）**: 「読み」だけを発話すると登録した本文へ展開（例:「じゅうしょ」→ 会社の住所全文）
- **押している間だけ録音（Push-to-talk）**: ホットキーの操作方式をトグルから切り替え可能
- **アプリ別の入力方式**: 直接入力で文字が入らないアプリだけクリップボード貼り付けにする、といった上書きが可能
- **テキスト整形**: 日本語間の不要な半角スペース除去（既定 ON）、文末「。」自動挿入（既定 OFF）
- **操作音**: 録音の開始/停止時に短い音でフィードバック（設定で無効化可）
- **30 秒無音の自動停止**: 無音が 30 秒続くと自動的に停止
- **録音中オーバーレイ**: マウスカーソルがあるモニターの下部中央に、マイクアイコン＋音量連動の波形＋認識中テキストをフェード表示
- **辞書登録**: 誤認識語 → 正しい語の対応を認識後に強制置換。Excel からの 2 列貼り付け、CSV エクスポート/インポート対応
- **タスクトレイ常駐**: 待機中はモノクロ、録音中は赤系、エラー時はオレンジ系にアイコンが変化
- **ブラウザ選択**: Windows の既定ブラウザに追従（Chrome / Edge）。設定で明示指定も可能
- **端末内認識（プライバシー）**: 対応ブラウザでは音声をクラウドに送らず端末内で認識（設定で有効化・非対応時は自動フォールバック）
- **ブラウザ自動復旧**: 認識用ブラウザが不意に終了した場合は自動で再起動
- **ログ**: エラー・動作ログを `%APPDATA%\VoiceDock\logs` に日別保存（30 日で自動削除）。種別フィルタ・コピー・一括削除に対応。**認識したテキストは既定ではファイルに保存しません**（設定で有効化可）
- **二重起動制御 / スタートアップ登録 / ダークテーマ固定の設定画面（即時反映）/ 初回起動ガイド**
- **タイトルバーのテーマ連動（Windows 11）**: 設定・辞書管理・ログ画面のタイトルバーをアプリの配色に合わせてダーク表示。Windows 10 以下では OS 標準のタイトルバーのまま動作
- **自動更新**: 起動のたびに GitHub Releases を確認し、新しい版があればダウンロード・SHA256 検証・入れ替え・再起動まで自動で行います（「1 日 1 回まで」「手動のみ」にも変更できます）

## 対応環境

- Windows 10 / Windows 11
- **Chromium 系ブラウザ**（Microsoft Edge または Google Chrome）が必要です。既定では Windows の既定ブラウザに追従し、Chrome が既定なら Chrome、それ以外は Edge を使用します（設定で明示指定も可能）
- インターネット接続が必要です（クラウド認識のため。端末内認識を有効にし言語パックが導入済みの場合は不要）
- 配布形式: 単一 exe（署名なし・インストーラーなし）。任意の場所に置いて実行するだけ

## インストール / アンインストール

- **インストール**: `VoiceDock.exe` を任意の場所に配置して実行
- **アンインストール**: exe 本体と `%APPDATA%\VoiceDock` フォルダを手動削除
- **アップデート**: 新しい版が出ると通知され、その場で更新できます（トレイメニューの「更新を確認」からも実行可）

## 使い方

1. 起動するとタスクトレイに常駐し、認識用のブラウザが裏で起動します（画面には出ません）
2. テキスト入力欄にカーソルを置き、ホットキー（初期値: `Ctrl+Space`）を押すと認識開始
3. 話すと、確定したフレーズが順次その場に入力されます
4. もう一度ホットキーを押すと停止します

タスクトレイアイコンの右クリックメニューから「録音開始/停止」「直前の入力を取り消す」「設定」「辞書管理」「定型文」「ログ表示」「更新を確認」「終了」を開けます。

## 設定・データの保存場所

`%APPDATA%\VoiceDock` 配下にすべて保存されます。

| ファイル / フォルダ | 内容 |
|---|---|
| `settings.json` | ホットキー・ブラウザ・入力方式・整形などの設定（`.bak` に 1 世代分の控えを保持） |
| `dictionary.json` | 辞書（誤認識語 → 正しい語） |
| `snippets.json` | 定型文（読み → 展開後の本文） |
| `browser-profile/` | 認識用ブラウザの専用プロファイル（マイク許可等を保持） |
| `logs/` | 日別ログ（30 日で自動削除） |

## 辞書 CSV の運用上の注意

エクスポートした CSV には**社内用語・人名が含まれます**。社外への持ち出しや共有 NAS 等での取り扱い・保存先には十分注意してください。CSV は Excel で一括編集して再インポートする運用を想定しています（1 列目: 誤認識語、2 列目: 正しい語、UTF-8）。

## ビルド方法

.NET 8 SDK が必要です。単一 exe の生成:

```powershell
dotnet publish src/VoiceDock/VoiceDock.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -o publish
```

`publish/VoiceDock.exe` が生成されます。GitHub Actions（`.github/workflows/build.yml`）でも同じ手順でビルドし、アーティファクトとして exe を取得できます。GitHub Release は Actions の「Run workflow」から作成できます（Actions の無料枠を無駄に消費しないよう、タグ push では起動しません）。

## 実装メモ・既知の制限

- **認識にはブラウザが必要**: Web Speech API は埋め込み(WebView2)では動作しないため、Chromium 系ブラウザを裏で起動して利用します。使用ブラウザは Windows の既定ブラウザに追従（Chrome が既定なら Chrome、それ以外は Edge）。設定画面で「常に Edge」「常に Chrome」も選択できます（変更後は再起動で反映）
- **マイク許可**: 認識ページ（127.0.0.1）へのマイク許可は起動フラグ（`--use-fake-ui-for-media-stream`、専用プロファイルの隔離インスタンス）で自動付与します
- **既定ホットキー `Ctrl+Space`**: 一部の日本語 IME では `Ctrl+Space` が IME のオン/オフ切替に割り当てられていることがあります。競合する場合は設定画面から別のキーに変更してください
- **IME 変換中のホットキー無視**: 他プロセスの未確定文字列を直接取得する公開 API が無いため、IME 候補ウィンドウ等の表示状態からのベストエフォート判定です
- **エラー通知**: Windows 標準バルーンではなくアプリ固有のトースト風ポップアップで通知します
- **辞書ヒント**: Web Speech API は認識前のヒント指定に対応しないため、辞書は認識後の強制置換のみで反映します
- **日本語 IME との競合対策**: 直接キー入力(SendInput)方式では、日本語 IME がオンだと送った文字が IME の変換バッファに吸い込まれ、後からまとめて逆順で確定される（変換された語だけが文末に逆順で並ぶ）現象が起きます。対策として、送信中だけ対象アプリの IME を一時的にオフにし（既定 IME ウィンドウへの `WM_IME_CONTROL`。他プロセスのウィンドウにも効く方式）、送信を直列化しています。それでも崩れる場合は、設定の入力方式を「クリップボード貼り付け」に切り替えると IME を完全に迂回できます
- **句読点の自動挿入**: 「発話の区切りごとに文末へ。を自動挿入」は既定 OFF です。Web Speech API は息継ぎでフレーズを区切るため、1 文を途中で区切って話すと文中に。が入ってしまうためです。句読点は音声コマンド（「まる」「てん」）で明示的に入力する方式を推奨します
- **改行の送り方**: 「改行」コマンドは Unicode 文字ではなく実際のキー入力として送ります。既定の **Shift+Enter** はメモ帳やエディタを含む大半のアプリで改行になり、かつ Enter が「送信」になるチャットアプリ（Claude Desktop・Slack・Teams 等）でも誤送信しないため、通常はこのままで問題ありません。Excel はセル内改行が Alt+Enter（Shift+Enter は上のセルへ移動）のため、設定から Alt+Enter を選べます
- **取り消しの仕組み**: 直前に入力した文字数ぶん BackSpace を送る実装です。入力後に手動で文字を打ったり、アプリ側で自動整形が入った場合は、意図した範囲と異なることがあります
- **押している間だけ録音**: RegisterHotKey はキーを押した瞬間しか通知しないため、押下後にキー状態をポーリングして離されたことを検出しています
- **端末内認識**: `SpeechRecognition.processLocally` を利用します。ブラウザが未対応、または日本語の言語パックが未導入の場合はクラウド認識にフォールバックします（未導入時は言語パックの取得を裏で開始し、次回以降に端末内認識へ切り替わります）。実際に使われたモードはログとトーストで確認できます
- **exe サイズ**: 自己完結（.NET ランタイム＋WPF 同梱）のため単一ファイル圧縮を有効化しています。ローカル音声認識ライブラリを外したことで旧構成より小型化しています
- **設定・辞書の保護**: 設定/辞書/定型文は一時ファイルへ書いてから差し替える方式で保存し、直前の内容を `.bak` として 1 世代残します。読み込み時に本体が壊れていれば `.bak` から復帰し、復帰できない場合は空の内容で上書きせずに保存を見送ります
- **自動更新の仕組み**: `UpdateService`（`Services/UpdateService.cs`）が GitHub Releases API で最新版を確認します。バージョン比較は文字列ではなく数値として行います（`1.0.10` < `1.0.9` の誤判定を避けるため）。更新時は「実行中の exe を `.old` へ改名 → 新しい exe を配置 → 新 exe を起動 → 自身は終了」という手順で自己置換し、失敗した場合はリネームを元に戻します（ロールバック）。`Program Files` など書き込めない場所に置かれている場合は自動更新せず、手動での差し替えを案内します。ダウンロードした一時ファイル（数十 MB）は、更新の適用後・検証失敗時・中断時のいずれでも削除します。それでも残った場合（強制終了など）は、`.old` とあわせて次回起動時に片付けます
- **タイトルバーのテーマ連動**: `TitleBarThemeHelper`（`Services/TitleBarThemeHelper.cs`）が DWM API (`DwmSetWindowAttribute`) を P/Invoke で呼び、タイトルバーの背景色・文字色・ダークモードをアプリの配色に合わせます。Windows 11（ビルド 22000 以降）でのみ有効で、それ未満の環境では例外を投げず何もしません。ウィンドウ側の配線は `UI/AppTheme.cs` が担い、将来テーマ切替（ライト/アクセントカラー）を追加した際は `AppTheme.SetDarkMode()` のような入口から開いている全ウィンドウへ即座に反映できる設計です

## 外部通信について

本アプリが外部と通信するのは次の場合だけです。使用状況の送信などは行いません。

| 用途 | 通信先 | 備考 |
|---|---|---|
| 音声認識 | ブラウザの音声認識サービス | 設定で端末内認識に切り替え可能 |
| 更新の確認・ダウンロード | GitHub (`api.github.com` / `github.com`) | 確認先 URL は `settings.json` の `UpdateApiUrl` で変更可。手動のみにもできます |

## 使用ライブラリ・ライセンス

外部の音声認識ライブラリは同梱していません（認識はブラウザの Web Speech API を利用）。UI・常駐・入力制御は .NET / WPF / Windows Forms（NotifyIcon）の標準機能で実装しており、追加の第三者ライブラリは使用していません。
